# gbif-taxonomy-for-la

Utilities to adapt a source taxonomy DwCA for its usage by LA portals.

## Source taxonomy: COL XR (was the GBIF backbone)

The GBIF Backbone Taxonomy is frozen (last release 2023) and GBIF itself has switched its
default taxonomy to the Catalogue of Life eXtended Release — see
[How to migrate from the legacy GBIF Backbone Taxonomy to Catalogue of Life Extended Release](https://data-blog.gbif.org/post/catalogue-of-life-taxonomic-backbone/),
[Taxonomy interpretation (GBIF techdocs)](https://techdocs.gbif.org/en/data-processing/taxonomy-interpretation)
and the [Catalogue of Life Checklist dataset](https://www.gbif.org/dataset/7ddf754f-d193-4cc9-b351-99906754a03b)
(the old backbone identifiers stay supported for backwards compatibility).

So this repo now builds from the COL XR DwCA, downloaded from
[ChecklistBank](https://www.checklistbank.org/):

    https://download.checklistbank.org/col/xr_latest_dwca.zip

Override `SRC_TAXONOMY_URL` to pin a dated COL release, or to fall back to the legacy backbone
(`https://hosted-datasets.gbif.org/datasets/backbone/current/backbone.zip`).

The artifact names still carry the historical `gbif-backbone` prefix
(`namematching-gbif-backbone-lucene-8-<release>.tgz`, `gbif-backbone-<release>.zip`) so existing
LA inventories and download URLs keep working; the *contents* come from COL XR. Column layout is
resolved from the DwCA header by Darwin Core term, so both schemas work (COL prefixes its terms,
e.g. `dwc:language`).

## Introduction

This is a set of utilities to convert the source taxonomy for its usage by LA portals. This consists in:

- Download the current source taxonomy DwCA and [some dependencies](https://github.com/AtlasOfLivingAustralia/ala-name-matching)
- Separate `scientificName` and `scientificNameAuthorship` in `Taxon.tsv`
- Generate a subset of the original `VernacularName.tsv` file based on the `language` field.
- Detect issues during this conversion that can be reported upstream (see `target/backbone/issues.tsv`).
- Workaround for some issues in the taxonomy that prevent the nameindexer to work properly.
- Generate lucene 6 and lucene 8 indexes for use by LA portals (for nameindexer, namematching-service and sensitive-data-service)
- Generate the modified dwca for bie-index
- Package the taxonomy for [atlas-index](https://github.com/AtlasOfLivingAustralia/atlas-index)'s search-service (see below)

The resulting indexes are published in updated [LA ansible inventories](https://github.com/living-atlases/generator-living-atlas/blob/master/generators/app/templates/quick-start-inventory.ini#L61) (those generated by the la-toolkit), so in general you can use these indexes without the need to run this repository (that is quite disk and time consumming).

## Dependencies

This tool use docker that downloads all the dependencies.

## Usage

Some usage help:
```
docker build . --tag gbif-taxonomy-for-la 
```
 and with the image ready:

```bash
./gbif-taxonomy-for-la-docker --help

Options:
      --backbone                    Download the source taxonomy DwCA
      --name-authors                Split name and authors from the source taxonomy
      --prepare-tests               Prepare tests
      --tests                       Run tests
      --regression                  Run the golden-set regression gate (needs a built index)
      --filter_lang=<langs>         Filter VernacularName.tsv file for given language [default: ].
      --namematching-distri=<nmv>   Download ALA namematching-distribution version [default: 4.3].
      --namematching-index          Generate namematching index
      --namematching-index-legacy   Generate namematching index legacy (pre namemaching-service)
      --dwca                        Regenerate the dwca zip
      --atlas-index                 Package the taxonomy for atlas-index's search-service (needs the Lucene 8 index)
      --help                        Show help options.
      --version                     Print program version.
```

`--backbone` keeps its name for compatibility, but it now downloads COL XR (see above).

Download the source taxonomy:

```bash
./gbif-taxonomy-for-la-docker --backbone 2026-07-23
```
Optionally, filter common names from VernacularName.tsv based on language passed as comma seperated list:

```bash
./gbif-taxonomy-for-la-docker --backbone --filter_lang=en,sv 2026-07-23
```

Full process, download nameindex, select lang, split `scientificName` and `scientificNameAuthorship`, and generate indexes and recreate the modified dwca using a date as file suffix:

```bash
./gbif-taxonomy-for-la-docker --backbone --filter_lang=en,sv --name-authors --namematching-distri=4.3 --namematching-index --namematching-index-legacy --dwca 2026-07-23-sv
```

Just generate the indexes:

```bash
./gbif-taxonomy-for-la-docker --namematching-index --namematching-index-legacy 2026-07-23
```

Environment overrides (all optional):

- `SRC_TAXONOMY_URL` — source DwCA URL (default: COL XR latest).
- `SKIP_DOWNLOAD=1` — reuse the cached archive under `target/cache/` instead of checking the remote.
- `NM_INDEX_XMX` / `NM_INDEX_XMS` — indexer heap (default `8g` / `1g`); the wrapper forwards them into the container.
- `NM_SERVER_VER` — ala-namematching-server version used by `--tests` / `--regression` (default `1.8.1`).

## atlas-index (search-service)

atlas-index's search-service, the successor of bie-index, imports the taxonomy from an unpacked
DwCA, but also needs two CSVs that only the namematching index has: the left/right values and the
preferred common name as ala-namematching-service resolves them. `--atlas-index` runs
atlas-index's [`names-extract`](https://github.com/AtlasOfLivingAustralia/atlas-index/tree/develop/names-extract)
(built into the image, pinned with the `ATLAS_INDEX_REF` build arg) against the Lucene 8 index
built in the same run, and packages everything as `atlas-index-<release>.zip`:

    atlas-index-<release>/
      dwca/<release>/              -> search-service dwca.dir (one sub-directory per DwCA)
      lsid-left-right.csv          -> dwca.extract.leftRightCsvPath
      lsid-vernacularName.csv      -> dwca.extract.commonNamePath

DwCA, CSVs and index come from the same taxonomy, so the ids match. With `--prepare-tests` the
DwCA extensions are cut down to the subset's taxa too, which gives a small, consistent package
for development and CI:

```bash
./gbif-taxonomy-for-la-docker --backbone --prepare-tests --namematching-index --atlas-index testsubset
```

## CI (Jenkins) build & publish

The heavy build runs on Jenkins (see [`Jenkinsfile`](Jenkinsfile)) — it downloads the
source taxonomy and builds the multi-GB Lucene indexes, so it is not meant for a laptop.
Relevant job parameters:

- `INSPECT_SCHEMA` — spike only: dump the COL DwCA `meta.xml` + sample rows
  ([`scripts/inspect-col-schema.sh`](scripts/inspect-col-schema.sh)) and stop. Defaults to
  `true`, so set it to `false` for a real build.
- `TEST_MODE` — fast dev loop: build the index from a ~6k-taxon subset, the Carnivora clade (plus the tested
  species and their ancestor lineage) and run the mocha suite. Minutes instead of a full run.
- `PROFILE` — `generic` (all vernaculars) or `es` (the gbif-es index). `es` forces
  `FILTER_LANG=es,eu,ca,gl` when empty and appends `-es` to `RELEASE`, so it reproduces the
  old manual recipe (`--filter_lang=es,eu,ca,gl ... <date>-es`) with a single dropdown.
- `RELEASE` — release suffix used in every artifact name, e.g. `2026-07-23` (or
  `2026-07-23-es`, added automatically with `PROFILE=es`).
- `LEGACY_INDEX` / `BUILD_DWCA` — also build the Lucene 6 index and the modified DwCA.
- `BUILD_ATLAS_INDEX` — also build `atlas-index-<release>.zip` (see above), in full builds and
  in `TEST_MODE`. Published to `/namedata` next to the DwCA.
- `RUN_REGRESSION` — run the golden-set gate ([`scripts/regression-gate.sh`](scripts/regression-gate.sh))
  against the freshly built index and fail the build on regressions.
- `PUBLISH` (+ `PUBLISH_SSH_CRED` / `PUBLISH_SSH_KEY`, `PUBLISH_HOST`, `PUBLISH_USER`,
  `PUBLISH_OTHERS_PATH`, `PUBLISH_NAMEDATA_PATH`, `PUBLISH_URL_BASE`, and the
  `PUBLISH_DEMO`/`DEMO_*` mirror) — when true, [`scripts/publish.sh`](scripts/publish.sh)
  sha1sums the deliverables, rsyncs the `.tgz` to `/others` and the DwCA `.zip` to
  `/namedata` on the download host, creates the historical `nameindex-*` aliases
  (server-side symlinks), and emits `target/inventory-snippet-<release>.ini` — a
  ready-to-paste fragment (URLs + `sha1:` checksums + datestamp) for la-toolkit's
  `gbif-es-local-extras.ini`.

Every build (and `publish.sh` again, before uploading) runs
[`scripts/verify-artifacts.sh`](scripts/verify-artifacts.sh), which opens the packaged
`.tgz` and checks its structure against the known-good layouts in
[`test/golden/`](test/golden): single root dir, a `segments_*` file in every sub-index, a
non-hollow `cb/`, and a `metadata.json` whose `luceneVersion` matches the artifact name.

Publishing authenticates either with a Jenkins SSH credential (`PUBLISH_SSH_CRED`) or with an
on-disk key on the agent (`PUBLISH_SSH_KEY`, default `/var/lib/jenkins/.ssh/jenkins_datos_gbif_es`),
and needs write access to the docroots served at `/others` and `/namedata`. `datos.gbif.es` is
round-robin DNS over independent backends that each keep their own copy, so the parameters point
at **fixed backend IPs** and both backends are published (`PUBLISH_HOST` + `PUBLISH_DEMO`/`DEMO_HOST`).

## Tests

`--prepare-tests` builds a self-consistent subset (the whole Carnivora clade, ~6k taxa, **plus**
the tested taxa and their full ancestor lineage — COL XR's row order differs from the old backbone, so the parents
are not in the first rows), and `--tests` runs the transform checks plus the mocha suite against
a namematching server. The index must exist before `--tests`, so it takes two runs:

```bash
./gbif-taxonomy-for-la-docker --backbone --prepare-tests --namematching-index 2026-07-23

./gbif-taxonomy-for-la-docker --tests 2026-07-23
```

`--regression` replays the golden set in [`test/golden/`](test/golden) against a built index and
fails on any regression:

```bash
./gbif-taxonomy-for-la-docker --regression 2026-07-23
```
